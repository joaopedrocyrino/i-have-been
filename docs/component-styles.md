# Component styles

Styles belong to the component that renders the corresponding UI. Companion
files such as `Components/Experiences/StarRating.razor.css` are compiled by
Blazor into CSS with selectors scoped to that component.

## Loading

- `DisableScopedCssBundling` disables the default application-wide stylesheet.
  The .NET SDK publishes each compiled companion file separately.
- A styled component renders `<ComponentStyles For="@typeof(StarRating)" />`
  alongside its markup. The helper resolves the native static-asset path and
  emits a stylesheet link. A parent uses `<StarRating />` without managing CSS.
- Initial HTML includes links for components already rendered, including static
  login/register pages. Interactive components introduce their links when they
  appear: opening an editor loads its dialog and nested control styles.
- An `@using` directive or a component in an inactive `@if` branch does not cause
  a stylesheet download. Components without their own styling need no CSS file.
- Each stylesheet includes that component's responsive rules and interactive
  states. This is loading by rendered component, rather than deleting selectors
  according to the current DOM. States remain available when they are needed.
- `wwwroot/app.css` contains shared theme tokens, resets, typography and common
  controls. Leaflet CSS is loaded by `MapCanvas`, so account pages omit it.

## Shared presentation

- `AuthShell`, `DialogShell`, `MapCanvas` and `MapHeader` own styles for UI used
  by multiple pages/components. Page components focus on routing and content.
- `JournalShell` owns the responsive journal frame and mobile metrics card;
  `JournalPanel` owns list/content styles. Its native `details`/`summary` control
  is collapsed on mobile and open on desktop. `journal.js` handles responsive
  initialization, Escape, selection collapse and measured map-control offsets
  on both the Blazor owner page and the static shared page. The native open state
  is deliberately kept outside server state, so list rerenders retain disclosure
  state. The shell provides the stable journal scope used by shared list styles.
- Use `::deep` from a component's HTML container for styles targeting content
  rendered by a child component or a `RenderFragment`. Ordinary isolated
  selectors apply only to HTML generated by their own Razor file.
- The read-only shared journal still builds memory content in JavaScript. Its
  initial page loads the journal-list style; opening a memory loads details,
  experience and rating styles through `component-styles.js` before showing it.
- Those four reusable presentation styles have explicit scope identifiers in
  the Web project. The shared viewer uses matching root attributes, allowing
  it to reuse the same CSS without copying rules or loading owner dialogs.
- The JavaScript loader reuses in-flight/completed requests. It does not remove
  styles after closing a shared memory. A version guard prevents a pending
  selection from reopening content after invitation revocation clears it.

## Adding a styled component

1. Add `MyComponent.razor.css` beside `MyComponent.razor`.
2. Render `<ComponentStyles For="@typeof(MyComponent)" />` in that component.
3. Keep the namespace aligned with its path under `Components/`; the helper uses
   that convention to resolve `/Components/.../MyComponent.razor.rz.scp.css`.
4. Put shared presentation in a reusable component; retain global tokens in
   `app.css`. Do not import every companion stylesheet from `App.razor`.
5. Rebuild the Docker image for the local app, or use the native .NET development
   workflow. The SDK handles CSS transformation and publishing without Node.

The browser suite verifies requested stylesheet URLs and computed styles for
initial pages, dialogs, nested ratings and the shared viewer.

Reference: [Microsoft: Blazor CSS isolation and disabling automatic bundling](https://learn.microsoft.com/en-us/aspnet/core/blazor/components/css-isolation?view=aspnetcore-10.0).
